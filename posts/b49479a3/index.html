读回全是 0xFF：SPI 模式配反了

新传感器 SPI 读 ID 全是 0xFF，根因是驱动模板沿用了旧器件的 CPHA 设置，主机与从机采样沿不一致；改回模式 0 并加上电 ID 自检后恢复。

问题背景

新项目的主控还是 STM32F4 + FreeRTOS，SPI4 上挂一颗压力传感器。驱动直接从旧项目的 SPI Flash 驱动改过来：时钟、片选、DMA 收发都是现成的，只把命令字节和寄存器地址换成了新器件的定义。

硬件是打样回来的板子，飞线、上拉电阻、片选都按参考设计做的。按以往经验，SPI 这种总线只要线接对了、时钟给上，读个 ID 寄存器应该是最简单的一步。

故障现象

上电读传感器的 WHO_AM_I 寄存器，返回值一直是 0xFF。这个值太有迷惑性了：MISO 空闲被上拉是高电平，读出来全 1，第一反应就是「从机没响应」——没供电、片选没拉低、MISO 断线、上拉电阻缺失，甚至怀疑芯片没焊好。

把 SPI 时钟从 8MHz 降到 1MHz 后，偶尔能读到正确的 ID，但十次里错七八次；降到 500kHz，成功率更高一些，但仍然不稳定。同样的驱动换到另一块板子上（挂的是另一颗 SPI 从机），读 ID 一切正常，说明 MCU 的 SPI 外设本身没坏。

排查过程

先按「从机没响应」的方向查硬件：万用表量供电和地，正常；示波器看片选，拉低时序正常；看 SCK，8MHz 方波干净，没有明显过冲；看 MISO，有跳变，不是一直被拉高。上拉电阻 10k 也在位。硬件层面看不出问题。

再用逻辑分析仪抓一次完整读事务，同时用两种方式解码。按主机当前配置（CPOL=0、CPHA=1）解码，MISO 上全是 0xFF；把解码器改成 CPOL=0、CPHA=0 重新解一遍，立刻显示出正确的 ID 和状态字节。同一段波形，两种解码方式结果完全不同——这说明从机是按「第一个时钟沿采样」工作的，而主机是在「第二个时钟沿」采样的。

回头看驱动初始化，CLKPhase 配的是 SPI_PHASE_2EDGE，也就是 CPHA=1，SPI 模式 1。旧项目的 SPI Flash 正好要求模式 1，模板原样抄过来时没改。新传感器的数据手册写得很清楚：CPOL=0、CPHA=0，模式 0。

到这里「低速偶尔能读对」也解释通了：主机在第二个边沿采样，而从机在第一个边沿更新数据，采样点正好压在数据跳变的边缘。低速时信号有足够时间稳定，采样点歪打正着落在有效窗口里；8MHz 时建立/保持时间不够，采到的就是错位的数据，全 0xFF 只是错位后的表象。

顺手确认了片选时序：CS 拉低到第一个时钟沿有足够建立时间，最后一个时钟沿到 CS 拉高也满足保持时间；软件 NSS 控制正常。这部分不是主因。

解决方案

  1. 改回模式 0：CLKPhase 改为 SPI_PHASE_1EDGE，CLKPolarity 保持 SPI_POLARITY_LOW，重新初始化 SPI4。
  2. 参数化驱动模板：把 SPI 模式、时钟频率、CS 建立/保持时间做成配置项，新器件接入时按数据手册填写，不再手工改初始化代码。
  3. 加上电自检：初始化后先读 WHO_AM_I，与数据手册的固定值比对，不匹配就报错并停止后续采集，避免带着错位数据继续跑。
  4. 验证：8MHz 下连续读 10 万次 ID 与状态寄存器，零错误；再把时钟拉到 12MHz 做余量测试，数据仍稳定；断电重启 50 次，自检全部通过。

根因分析

SPI 有四种模式，由 CPOL（时钟空闲电平）和 CPHA（采样边沿）两个参数组合决定。主机和从机必须使用同一种模式，否则采样的边沿对不上，读回的数据就会整体错位。这是 SPI 与 I2C 最大的不同：I2C 有起始条件、地址和 ACK 可以把关，SPI 没有任何协议层的纠错，配错了只会得到「看起来像数据」的错误值。

0xFF 之所以容易误导，是因为它同时是「MISO 浮空/从机无响应」的典型读数。硬件排查全部正常之后，就应该怀疑时序，而不是继续在接线和焊接上打转。这次真正破案的是逻辑分析仪的同波形双模式解码——同一段波形，模式 1 解出全 FF，模式 0 解出正确 ID，主机与从机的差异一目了然。

「低速偶尔能通、高速全错」是采样边沿错位的典型特征，说明问题在建立/保持裕量，而不是逻辑电平。把它当成「信号质量不好」去换线、加电容，方向就偏了。另外 SPI 没有 I2C 那样的时钟拉伸与应答机制，主机节奏就是总线节奏，模式错位时连重试都救不回来。

预防措施

  • 新器件接入清单：SPI 模式（CPOL/CPHA）、时钟上限、CS 建立/保持时间、MISO 上拉要求，四项逐条对照数据手册确认后再写代码。
  • 驱动模板参数化：模式、频率、片选方式全部走配置，禁止在新项目里直接复制旧初始化代码后手工改参数。
  • 上电 ID 自检：所有带 ID 寄存器的器件都在初始化时读一次并比对，失败就停在明确错误上，不带病运行。
  • 时序图评审：驱动 review 时对着数据手册的时序图逐项核对，而不是只看代码能不能编译、能不能读到数。
  • 调试工具常备：逻辑分析仪解码 SPI 时，同时保存主机配置和从机配置两种解码结果，是定位模式问题最快的方法。
  • 低速验证不等于通过：低速能通只能说明电气上连上了，不能说明时序正确；功能验证必须在标称最高频率下做批量读。

总结

SPI 的四种模式没有「默认值」，只有「从机要求值」。驱动模板是给旧器件写的，换器件不核对手册，模式配反了就会得到一屏 0xFF，而 0xFF 又恰好长得像「线没接好」。

这次排查真正的转折点，是意识到「全 FF」不一定是没数据，也可能是采样错了位置。先怀疑时序、再看电平，顺序反过来，往往要在硬件上白折腾很久。
