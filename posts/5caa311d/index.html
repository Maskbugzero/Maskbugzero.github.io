CGNAT 背后：端口映射配得再对也不通

宽带 WAN 口拿到 100.64 开头的运营商共享地址，端口映射只作用于用户侧 NAT，公网流量到不了路由器；申请公网 IPv4 或改用 IPv6 后恢复。

问题背景

分支机构有一台监控主机放在内网，需要从外网访问。路由器上为它做了端口映射：外网 8443 转发到内网 192.168.10.20:8443，同时配了 DDNS，访问域名解析到这条宽带的地址。这套写法在之前的办公点用过很多次，一直没出问题，所以这次换宽带后也照搬了配置。

分支机构能正常上网，视频会议、云盘都没问题，看起来一切正常。

故障现象

外网访问 https://<DDNS 域名>:8443 一直超时：用手机 4G、用家里宽带、用其他办公点都试过，全部连不上。换端口 8000、2222 重新映射，同样不通。内网访问监控主机完全正常，路由器本机的防火墙也确认放行了对应端口。

最迷惑人的一点是：DDNS 解析出来的地址和路由器状态页里的 WAN 口地址一致，看起来「地址没配错、域名也对」，于是怀疑过应用监听、证书、运营商封锁端口，查了一圈都不是。更让人费解的是，同一台路由器、同一份配置，在之前的办公点（那家宽带提供公网地址）是能通的，这基本排除了「配置写错」的嫌疑。

排查过程

先把边界以内的链路验证一遍：内网 curl 192.168.10.20:8443 正常，路由器本机 curl 内网地址正常，说明服务本身和路由器 LAN 侧都没问题。

接着核对 WAN 口地址。路由器状态页显示 WAN IP 是 100.64.x.x。这个地址段不是公网地址，也不是常见的 192.168/10/172.16 私网段——它是 RFC 6598 保留的运营商级 NAT（CGNAT）共享地址空间。

再查真实出口地址：从内网访问外部「查询我的 IP」服务，返回的公网地址与 WAN 口地址完全不同。到这一步基本确认：路由器 PPPoE 拨号是成功的，但它拿到的是运营商内网地址，公网出口在运营商那一侧。

抓包做最后确认。在路由器 WAN 口用 tcpdump 过滤 tcp port 8443，同时从手机发起访问——路由器上一个 SYN 都没抓到。说明流量根本没到达用户侧，端口映射连执行的机会都没有。又请同事从另一条宽带上访问，结果同样是超时：访问源不同，指向的却是同一个问题。

排除法收尾：防火墙规则全部放行后仍不通；换 8443/8000/2222 三个端口全不通，排除单一端口封锁；光猫已是桥接模式，路由器拨号拿到地址，排除双层私网；DDNS 解析正确，排除域名问题。

三条证据凑齐：WAN IP 属于 100.64.0.0/10、WAN IP 与公网出口 IP 不一致、WAN 口抓不到入向 SYN。结论是宽带被运营商放在了 CGNAT 后面，多个用户共享同一个公网地址，入向连接无法定位到具体用户。

顺带确认了 UPnP/NAT-PMP 无效：它只能操作路由器自己的 NAT 表，运营商上游的 CGNAT 不归它管——除非运营商支持 PCP 之类的协议，家用宽带基本见不到。

解决方案

方案 成本 适用场景 注意点
申请公网 IPv4 低 需要固定公网访问 确认是「动态公网」且重拨后地址仍可用
IPv6 直连 低 运营商下发前缀、访问端支持 IPv6 防火墙放行、AAAA 记录、IPv4 回退
内网穿透 中 无公网 IP、服务数量少 需 VPS/域名，带宽延迟受中转影响
overlay VPN 低 运维人员自己访问 不适合面向公众用户

我们最终向运营商申请了动态公网 IPv4（该套餐免费），申请通过后端口映射立即生效；同时把 IPv6 访问配好作为备份路径。

验证项：外网 4G 访问 8443 成功；路由器 WAN IP 与外部查询到的出口 IP 一致；重启光猫和路由器后 DDNS 能正确更新；IPv6 地址从外部可直接连通。

根因分析

CGNAT 的工作方式是在运营商汇聚层做一次大 NAT，把成百上千用户映射到同一个公网 IP 的不同端口上。用户侧路由器的端口映射只写在自己的 NAT 表里，公网流量在运营商那层就被分流了，根本到不了用户的 WAN 口，映射规则自然永远不会命中。

100.64.0.0/10 是 RFC 6598 专门留给运营商级 NAT 的共享地址段。看到 WAN 口是这个段，第一反应就应该是 CGNAT，而不是「私网地址配错了」。

还需要澄清两个常见误解：第一，「WAN IP 等于出口 IP」只是端口映射生效的必要条件，不是充分条件，防火墙和运营商端口封锁仍可能挡路；第二，DDNS 解析到 CGNAT 地址没有意义，那个地址在公网不可路由。至于「宽带能上网」和「宽带有公网 IP」，本来就是两件事，安装验收单上一般不会写。

预防措施

  • 开通前先问清：办理或迁移宽带时确认「是否提供独立公网 IPv4」；装机完成后立即验证 WAN IP 与外部出口 IP 是否一致，一条查询就能测。
  • 上线前画链路图：远程访问方案上线前先判断 NAT 层级（CGNAT / 单层 / 双层），把「光猫—路由器—运营商」画清楚，再谈端口映射。
  • 优先 IPv6：运营商普遍下发 IPv6 前缀，远程服务先做 IPv6 可达性测试，并保留 IPv4 回退路径。
  • 监控比对：DDNS 记录与出口 IP 定期比对，不一致即告警；外网端口拨测纳入监控，不要只监控内网。
  • 地址段知识沉淀：把 100.64.0.0/10 与 10/8、172.16/12、192.168/16 的区别写进团队知识库，避免把 CGNAT 地址当成「配错的私网地址」反复折腾。

总结

端口映射能生效的前提是「公网流量能到达你的 WAN 口」。CGNAT 把这条前提悄悄拿掉了，映射配得再标准，也只是在自家路由器上自娱自乐。

遇到外网访问不通，先看两件事：WAN IP 是不是 100.64 开头，以及它和真实出口 IP 是否一致。两分钟就能定方向，比反复改防火墙规则有用得多。
